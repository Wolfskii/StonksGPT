# Internationalization (i18n)

The StonksGPT frontend is localized so users can switch between **English** and **Swedish**. All user-facing strings go through the i18n layer; nothing is hardcoded in the UI.

## Overview

- **Locales:** `en` (English) and `sv` (Swedish) only for now.
- **Locale files:** JSON under `frontend/locales/`:
  - `frontend/locales/en.json`
  - `frontend/locales/sv.json`
- **Runtime:** `frontend/src/lib/i18n/index.js` – exposes `t(key)`, `locale` (Svelte store), `setLocale(loc)`, `initI18n()`, and `localeOptions` for the dropdown.
- **Persistence:** The chosen locale is stored in **localStorage** under the key `stonksgpt-locale` and restored on next visit.

## Using translations in the app

1. **In Svelte components:**  
   `import { t, locale, setLocale } from '$lib/i18n/index.js';`  
   Use `t('section.key')` for any string, e.g. `t('nav.dashboard')`, `t('common.loading')`.  
   To react to locale changes, read the store (e.g. `$locale` in the template or in `$derived.by(() => { $locale; return t('...'); })`).

2. **Keys are dot-separated paths** into the JSON. Example: `t('watchlist.suggestedMarkets')` reads `watchlist.suggestedMarkets` from the current locale file.

3. **Parameterized strings:**  
   `t('key', { name: 'Value' })` replaces `{name}` in the string. The locale files define the template, e.g. `"welcome": "Hello, {name}!"`.

## Adding or changing strings

- **Always edit both** `frontend/locales/en.json` and `frontend/locales/sv.json`.
- Keep the **same structure** in both files (same keys under the same sections). Add new keys in the same place in en and sv.
- Prefer grouping by feature: `app`, `nav`, `dashboard`, `watchlist`, `notes`, `history`, `common`, `disclaimer`, `locale`.

Example – adding a new section:

```json
// en.json
"newFeature": {
  "title": "New feature",
  "action": "Do something"
}

// sv.json
"newFeature": {
  "title": "Ny funktion",
  "action": "Gör något"
}
```

Then in code: `t('newFeature.title')`, `t('newFeature.action')`.

## Locale switcher

The UI uses a **dropdown (&lt;select&gt;)** with a **flag emoji** next to each language name (e.g. 🇺🇸 English, 🇸🇪 Svenska). The list is defined in `$lib/i18n` as **`localeOptions`**: each entry has `code`, `labelKey` (for `t()`), and `flag`. The dropdown is in `frontend/src/App.svelte`; the label uses `t('common.language')`.

## Initial locale

On first load, `initI18n()` (called from `frontend/src/main.js`) decides the locale in this order:

1. **localStorage** – if the user previously chose a locale, that is used.
2. **Browser language** – if `navigator.language` starts with `sv`, Swedish is used when there is no saved choice.
3. **Default** – otherwise English (`en`).

When the user changes the dropdown, `setLocale(loc)` updates the store and saves to localStorage.

## Adding a new locale (future)

To support another language (e.g. `de`):

1. Add `frontend/locales/de.json` with the same key structure as `en.json` and `sv.json`.
2. In `frontend/src/lib/i18n/index.js`:
   - Import the new file and add it to `messages`.
   - Add `'de'` to `supportedLocales`.
   - Add an entry to `localeOptions` (e.g. `{ code: 'de', labelKey: 'locale.de', flag: '🇩🇪' }`).
3. Add the label for the new locale in both existing locale files under `locale`, e.g. `"de": "Deutsch"`, and add `"locale": { "de": "Deutsch" }` (or the same key) in `de.json`.

## For AI and tooling

See **AGENTS.md** (section **i18n**) for concise instructions for AI coding agents: no hardcoded UI strings, use `t('key')`, add keys in both en and sv, and follow the locale switcher and persistence rules above.
